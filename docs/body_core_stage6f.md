## Объём и профиль кисти

Реализован один CPU-предмет, одна активная рука, один калиброванный хват
`LeftGrip` / `RightGrip`. Предмет — **сфера радиуса 22 мм**, диаметр 44 мм;
desktop показывает её проволочной сферой. Локальная рамка может иметь proper-
ориентацию и смещение до 5 мм от центра. Размер/форма фиксированы; произвольный
подбор хвата не реализован.

У каждой кисти пять цепей `c_index/middle/ring/pinky/thumb1 → 2 → 3` от
`hand.l_0160` / `hand.r_0139`: **30 фаланг**. Имена, родители, точные исходные
local-матрицы и quaternion-концы профиля записаны в `cpu/hand-rig.csv`.
Во всех 15 клипах есть по 30 finger-каналов; изменяющиеся вращения найдены
у `TEST_fingers_35` и `TEST_practical_ranges` (`cpu/finger-channels.csv`).
Левая bind-кисть уже согнута, правая почти распрямлена.

`HandLayer` строит proper-рамки из действительных bind-матриц и affine-адаптеры
`before * R * after`, сохраняя исходные преобразования. `ModelAsset` не меняется.
Выключенный слой оставляет входные locals **точно** неизменными. Калибровка
доступна только для чтения; параметры раскрытия принадлежат экземпляру.

`closure ∈ [0,1]` интерполирует откалиброванные вращения. Для четырёх пальцев
накопленные изгибы закрытой позы относительно ладони: 1,40 / 2,65 / 3,65 рад;
для большого пальца — 0,50 / 0,95 / 1,40 рад с отдельной оппозицией.
Левый/правый знаки различаются. Отдельный `blend` плавно переводит исходную
bind-кисть в открытую. Квинтика на **120 тиках** ограничивает оба параметра:
скорость ≤1,875/с, ускорение ≤5,78/с². Новая ручная цель принимается из покоя;
закрытие завершается только после нулевой дискретной скорости.

Приоритет: `clip/bind → direct body → hand → eyes → FK → palette`.
Кисть применяется только при direct mode и enabled соответствующей руки.
Обычные клипы при выключенном управлении сохраняются. Reset и ручное выключение
диагностического слоя имеют явную семантику разрыва вне действия.
Просмотрены обе кисти в открытии, захвате, переносе и отпускании с трёх ракурсов.
После первого просмотра исправлена оппозиция большого пальца. Итог:
`gpu/review.png`, `gpu/closeup.png`.

## Состояние, команды и преобразования

`HandInteraction` принадлежит `BodyInstance`, который остаётся единственным
писателем. Handle `{id,generation}` действует в пространстве адресованного тела;
поколение увеличивается при повторном создании и не сбрасывается при reset.
Объект хранит rigid world-позу, радиус, локальную рамку захвата, Free/Attached,
BodyId владельца, руку и постоянное `effectorFromObject`. Старые поколения
отклоняются. Свободный предмет неподвижен в мире, включая после reset тела.

Команды `CreateInteractionSphere`, `DeleteInteractionObject`, `GraspObject`,
`MoveHeldObject`, `ReleaseObject`, `CancelInteraction`, `SetHandClosure` проходят
прежние ID/target/tick/epoch. Applied означает принятие запроса;
фактический исход публикуется в `snapshot.interaction`.

Для column vectors, World W, Object O, Grip G и фактического эффектора E:

```text
T_WE_goal = T_WO * T_OG
T_EO      = inverse(T_WE_actual) * T_WO_actual       // прикрепление
T_WE_move = T_WO_goal * inverse(T_EO)
T_WO      = T_WE_actual * T_EO                      // удержание
```

Используются прежние метрические proper-рамки и rigid-root, без viewer-fit.
Последовательность: `Opening → Approach → Align → Closing → Holding → Transport
→ Holding → ReleaseOpening → Retreat → Succeeded`. Подход — на 75 мм назад
по локальной Z рамки захвата; совмещение — непосредственно с рамкой предмета.
Оба используют полный `PositionAndOrientation`, **2 мм / 1°**, settling **0,1 с**,
AllowDetour/FirstValid и один IK endpoint. Ориентация ограничена в конце Reach.

До раскрытия проверяется неподвижный увеличенный proxy кисти. Прикрепление
требует существующий свободный предмет, фактические ошибки в обоих допусках,
Succeeded после settling, закрытую неподвижную кисть и отдельную геометрическую
проверку будущего переносимого объёма. Таймер сам по себе ничего не прикрепляет.
`T_EO` вычисляется из фактических поз: подстановки идеального положения нет.

## Контакты и переносимый объём

До Align предмет остаётся препятствием для всех форм; эта проверка сохраняется
даже при выключающем предмет пользовательском mask. С Align до завершения
Retreat разрешена только пара **конкретная кисть — конкретный предмет**, в области
до 120 мм от grip. Cancel сохраняет политику уже принятого сегмента. При Attached
разрешён контакт сферы только с кистью владельца. Предплечье, корпус, другая
рука и остальные объекты продолжают проверяться с прежними фильтрами/self-pairs.

Для включённой кисти используется увеличенная капсула: local Y 25–160 мм,
радиус 45 мм. Это инженерный proxy, **не доказанная оболочка всего меша пальцев,
большого пальца и одежды**. Отдельной narrow phase фаланг и самоколлизий пальцев
нет. Геометрическая гарантия относится к поддерживаемым proxy и сфере.

Свободный collider — производная единственного CPU-состояния. При Attached он
удаляется из статической сцены; валидатор получает движущуюся сферу ID10 из FK
и постоянного `T_EO`. Двух одновременно действующих копий предмета нет.
Job копирует неизменяемую эффективную сцену, контактную политику и payload.
Смена представления/политики увеличивает scene version только на границе фаз
при остановленном Reach. Скрытых мутаций проверенного сегмента нет.
Для интерактивного collider зарезервирован старший бит ID.

Радиус границы перемещения — максимум прежней границы с запасом для увеличенной
кисти и **L_upper + L_fore + |wrist→effector| + |translation(T_EO)| + radius_object**.
Неравенство треугольника ограничивает любую точку сферы, включая вращение
смещённого предмета. Сохранены адаптивные межтиковые интервалы, условие
`gap > margin + slack + 2*R*sum(|dq|)/2`, margin 2 мм и slack 30 мкм.
Прежняя граница только для руки не используется для payload без расширения.

Бюджеты прежние: 24 позы / 2048 запросов за рабочий тик поиска, ≤4 полных
IK-итераций и ≤128 short-chain FK; 8192 позы / 250000 запросов / глубина 18
на сегмент. Фазовая проверка покоя занимает максимум две позы, отдельно
публикует poses/queries/time/scratch и не совмещается с работой планировщика.
Отказ конечного поиска не является доказательством отсутствия любого пути.

## Отпускание и особые операции

Release открывает кисть с сохранением attachment, затем фиксирует фактическую
world-позу, снимает владельца и начинает отход на 75 мм. Успех требует Reach
и проверки без контактного разрешения. При недостижимом/заблокированном отходе
возвращается `ReleaseBlocked`: предмет остаётся Free в фактической позе,
разрешение снимается. Обычный Reach после этого выявляет оставшееся исходное
пересечение. Удаление свободного предмета либо явная диагностическая перестановка
доступны как отдельные команды восстановления.

Cancel до attachment завершает разрешённый сегмент и движение пальцев,
открывает кисть и при необходимости отходит. После attachment он завершает
сегмент и оставляет **CancelledHolding** с тем же преобразованием. Это не Release.
Принятый Release атомарен до результата отхода; его Cancel явно отклоняется.
Неуспех переноса сохраняет attachment; из покоя доступны повторный Move/Release.

Во время владения взаимодействием или при Attached явно отклоняются ResetBody,
ResetCoordinates, смена режима, teleport root, ручные суставные команды,
внешние Reach/CancelReach, смена сцены и удаление предмета. При reset со свободным
предметом world-поза/handle сохраняются, кисть/фазы очищаются, эпоха увеличивается.
Старые эпохи команд отклоняются. Висячих ссылок и возврата предмета в начальную позу нет.

Наблюдения публикуют фазу, handle, владельца, руку, closure/blend, ошибки,
result/reason, расходы и **AssistedAttachment**. `gripForce = nullopt`: силы
недоступны. Для показа Attached-предмет вычисляется из **интерполированной**
рамки руки и постоянного `T_EO` в том же BodyDisplay.

## Воспроизведение

Зависимости установлены; новые не добавлены. Прямые CMake-команды требуют VS x64
Developer PowerShell. В sandbox Ninja завис до запуска компилятора; сборки
выполнены с разрешённым расширенным доступом. `cpu-dependencies.txt` подтверждает
отсутствие OpenGL/GLFW/GLAD у headless EXE.

```powershell
.\tools\build.ps1 -UseInstalledDependencies -KeepDiagnostics
cmake --preset cpu-release -DJULIA_WARNINGS_AS_ERRORS=ON
cmake --build --preset build-cpu-release --parallel 4
ctest --preset test-cpu-release
.\build\cpu-release\apps\julia_body_sim\julia_body_sim.exe --interaction-demo --ticks 1200 --no-eyes --output build/diagnostics/stage6f/example.csv
# Правая рука: добавить --right; World/root: --root 1.2 .3 -.4 .8
.\julia_desktop\julia_desktop.exe --verify-interaction build/diagnostics/stage6f/gpu
.\julia_desktop\julia_desktop.exe --window --no-save
```

В окне Ctrl+G запускает цикл. F2 и Shift+F7 позволяют заранее выбрать правую руку.
Ctrl+Shift+G отпускает неподвижный удерживаемый предмет; Ctrl+Delete отменяет
взаимодействие с описанной семантикой удержания. CLI/desktop используют общий
`apps/common/InteractionDemo.hpp` и те же команды.

## Что из широкого этапа 6 ещё не реализовано

- Произвольные предметы/размеры/хваты, выбор контактов, управление отдельными
  пальцами, точные коллизии меша и самоколлизии пальцев.
- Силовой захват, масса/инерция, усилия, трение, гравитация, падение, контактный
  solver/CCD физического backend и удержание под нагрузкой.
- Две взаимодействующие руки, передача между телами, общий многопредметный
  world-store и динамическая среда.
- Foot targets, перестановка стоп, опоры и движущиеся support frames, удержание
  стопы, COM, баланс и согласование root motion с фактическим движением.
- Общие ray/sweep/mesh queries, полный планировщик тела, глобальная полнота
  поиска и непрерывное ограничение ориентации вдоль маршрута.

Завершён ограниченный кинематический подэтап. Готовность всего виртуального тела,
физическая осуществимость и непрерывная самостоятельная деятельность ИИ
этим результатом не подтверждаются.
