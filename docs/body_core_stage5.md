## Проверенная область

Позиционный IK обеих рук в откалиброванном direct-режиме, с неподвижными
торсом, ключицей и корнем. Одна общая реализация, независимые действия рук.
Плечо — 3 координаты, локоть — 1, запястье — 2; исходные позы сторон различны.
Длины плеча/предплечья: L **0.264514/0.245795 м**, R **0.253742/0.245394 м**.
Профиль, bind, масштаб 0.4 м/resource unit, пределы и twist-доли не изменены.
Все выходы решателя — существующие координаты в радианах. GPU-матрицы не правятся.

`ReachTarget` явно задаёт руку, wrist/palm/grip, позицию в метрах, Body/World,
допуск, скорость координат, ускорение и время успокоения. Отступы palm и grip
участвуют в FK цели; sole и эффектор другой руки отклоняются. Ориентационная
задача **не реализована**: ориентация следует найденным координатам, достижимость
произвольной пространственной позы не обещается. Для wrist координаты запястья
сохраняются; для palm/grip доступны также две координаты запястья.

## Решатель и устойчивость

Аналитический двухзвенный IK дешевле и непосредственно даёт геометрический
локоть. Однако здесь его вращения пришлось бы переводить в ограниченные
последовательные оси относительно асимметричного bind, отдельно учитывать roll,
рамку шарнира и смещение эффектора. Простое последующее clamp нарушило бы цель.
Выбран небольшой численный **projected damped least squares** в координатах
профиля: 4 неизвестных для wrist, 6 для palm/grip, обратная матрица только 3×3.

Одна полная FK извлекает замороженную проксимальную рамку; пробные позиции
считаются по трём proper-рамкам. Jacobian — разности с шагом 0.001 рад,
односторонние у границ; нулевая ширина диапазона даёт нулевой столбец.
Демпфирование 0.005 м/рад, шаг координаты ≤0.15 рад, projected line search
принимает только уменьшение ошибки внутри пределов. Это ограниченное решение
на каждой итерации, а не clamp результата свободного IK.

Первый seed всегда предыдущая допустимая поза. При локальном неуспехе — до
8 детерминированных дополнительных seeds, максимум 160 итераций на seed.
Локоть наследует тёплый старт; движения между решениями ограничены по q/v/a.
При почти прямой руке демпфирование не допускает деления на сингулярный Jacobian.
Плоскость измеряется по плечу/локтю/запястью; при площади <1e-5 м² сохраняется
последняя нормаль. Знак нормали выбирается в прежней полусфере — плоскость
не меняется от смены знака нормали. Отдельного pole target нет.

`GeometricRange` означает выход из необходимой геометрической оболочки
`[max(0, |L1-L2|-offset), L1+L2+offset]`. Внутри неё неуспех классифицируется как
`JointLimited` при активной границе либо `LocalNoConvergence`. **Оба результата
локальные и не доказывают глобальную недостижимость.** Возвращаются лучшая
найденная допустимая поза, остаток и причина. Решатель не является полным
глобальным поиском и не гарантирует успех для каждой допустимой цели.

## Движение и исходы

IK решается при Start/Retarget внутри фиксированного тика. Затем строится
квинтический сегмент q(t), заканчивающийся нулевыми скоростью и ускорением.
Начальные q, аналитические v/a и предыдущая дискретная скорость сохраняются
при перенацеливании. Длительность увеличивается до прохождения проверки всех
тиков сегмента, включая два тика остановки: положения внутри диапазонов,
`|Δq|/dt ≤ vmax`, `|Δ²q|/dt² ≤ amax`. Внутренний запас — 0.5%/1% соответственно.
Проверенная плавность относится к сетке **120 Гц**; jerk не ограничен.
Это суставная траектория; прямолинейность пути и предел Cartesian-скорости
не заявляются. Измеренные скорости кисти приведены ниже отдельно.

Публикуются раздельно конечная `goalBody`, текущая FK-опора `referenceBody`
из траектории и фактическая `actualBody/World` после итоговой FK. Кинематический
исполнитель следует опоре с погрешностью float; совпадение не подменяет
проверку конечной цели. Render interpolation не продвигает траекторию.

Если новая квинтика нарушает пределы, `replanningDeferred=true`: завершается
прежний допустимый сегмент, затем строится новый из покоя. Поиск длительности
ограничен 50 с; отсутствие сегмента даёт `MotionPlanUnavailable`. Лимиты движения
нельзя менять у активного действия. **Cancel завершает текущий сегмент**, отменяет
отложенное перепланирование, успокаивается и удерживает координаты. Это не
немедленное торможение; задержка может достигать оставшейся длительности сегмента.
Публикуется `cancellationPending`; скрытого возврата в bind нет.

Состояния: Idle, Moving, Settling, Succeeded, Failed, Cancelled (CSV: 0–5).
Успех — измеренная ошибка ≤ допуска после полного сегмента и минимум 0.1 с
покоя по умолчанию. Одно окончание времени сегмента успеха не означает.

## Протокол и интеграция

`StartReach{target}` получает action ID своего command ID в текущей эпохе;
`RetargetReach{action,target}` сохраняет action ID; `CancelReach{arm,action}`
запрашивает описанную остановку. Queued/Applied означают приём/применение команды,
а не успех действия. `snapshot().reaches[2]` содержит состояние, ошибку,
фактическую позицию, цель/опору, локоть/плоскость, итерации и время solve.
`reachEvents()` сохраняет терминальные исходы текущего тика, включая Superseded.
Наблюдения нужно копировать до следующего шага; постоянный журнал не добавлен.

Порядок: адресованные команды → IK/траектория → direct adapter → глаза → FK /
палитра → измерение исхода → снимок. Прямые команды занятой руке, её ключице
и общим предкам до Chest отклоняются. Другая рука, шея/голова и глаза независимы.
Новый Start той же руке завершает прежнее действие как Superseded, сохраняя
движение. Переключение direct-режима, ResetCoordinates и телепорт корня явно
отменяют действия с отдельной причиной; это разрешённые разрывы вне обещания
плавности IK. ResetBody также очищает действия, очередь и пространство ID,
повышает эпоху. Старые эпохи отклоняются существующим протоколом.

Start из режима произвольного клипа явно Rejected. Для входа требуется отдельная
команда SetDirectMode: она имеет прежнюю явную семантику смены базы. IK не выводит
анатомические углы из клипа и не сбрасывает всю модель при запуске. Скрытый клип
можно независимо проигрывать/ставить на паузу. World-цель преобразуется обратным
rigid root; телепорт отменяет действие, диагностика продолжает показывать ошибку
к исходной мировой точке.

## Стоимость и память

Измерения без жёстких real-time гарантий: см. точные mean/p95/max в
`cpu/arm_reach.txt`; времена зависят от фоновой нагрузки. Решение 240 целей
заняло в среднем **63.90 мкс**, максимум **495.6 мкс** в последнем focused прогоне.
IK выполняется на командном тике; последующие тики только исполняют траекторию.
Времена включают обычные snapshot-копии. Отдельный тест **10 000 тиков** включает
новую команду на каждом тике, 40 retarget и `display(.5)` с его выделениями.

| Измерение | Среднее / p95 / максимум, мкс |
| --- | --- |
| Обычный тик без reach, 1200 тиков | 30.62 / 46.6 / 60.4 |
| Активное движение, 138 тиков, включая Start | 31.24 / 43.0 / 139.6 |
| Нагрузка: тик + display + команды, 10 000 тиков | 84.16 / 101.3 / 245.1 |

Две motion-ячейки фиксированы; `sizeof(ArmReach)` около 2 КБ плюс vector событий
одного тика. Start/Solve временно создают CPU Pose; steady advance такого буфера
не создаёт. Только locals/globals/palette каждого прежнего снимка — **86 208 байт**,
дополнительно хранятся компоненты, q, глаза и наблюдения. `display()` по-прежнему
создаёт свои массивы; очереди/события могут выделять память. Накоплено **10 042 ID**,
после reset логический размер **0**; capacity/buckets и память аллокатора могут
сохраниться. PrivateUsage процесса с импортированным ресурсом — около **1.74 ГБ**;
за нагрузочный прогон рост порядка **1 МБ**. Это память всего процесса, не IK.
Широкая оптимизация snapshot/display, текстур и политики хранения ID — отдельная
задача; текущий измеренный бюджет тика её не требует.

## Воспроизведение и управление

Команды подтверждены с установленными зависимостями (прямые cmake — из VS x64
Developer PowerShell). Ninja в sandbox снова не начинал работу; сборки выполнены
вне sandbox. CPU EXE зависит от Assimp/Windows/C++ runtime, без GL/GLFW/GLAD.

```powershell
.\tools\build.ps1 -UseInstalledDependencies -KeepDiagnostics
cmake --preset cpu-release -DJULIA_WARNINGS_AS_ERRORS=ON
cmake --build --preset build-cpu-release --parallel 4
ctest --preset test-cpu-release
.\julia_desktop\julia_desktop.exe --verify-ik build/diagnostics/stage5/gpu
.\build\cpu-release\apps\julia_body_sim\julia_body_sim.exe --ticks 1200 --reach .22 1.1 .32 --output build/diagnostics/stage5/headless.csv
.\julia_desktop\julia_desktop.exe --window --no-save
```

F2 — явный direct-режим; F7 — старт/retarget wrist; Shift+F7 — другая рука;
Z/C меняют X, V/N — Y, O/P — Z на 25 мм (Shift: 5 мм), затем F7 применяет цель.
Delete — завершить текущий сегмент и удержать. В начале title видны action/state,
ошибка и причина; overlay: пурпурная цель, голубая опора, зелёная кисть,
красная ошибка, голубые звенья/локоть и фиолетовая нормаль плоскости.
CLI дополнительно поддерживает `--right`, `--effector palm|grip`, `--world`,
`--root X Y Z yaw`, `--retarget X Y Z --retarget-tick N`, `--cancel-tick N`,
скорость/ускорение; CSV содержит строку на каждый тик. Код возврата процесса
подтверждает исполнение тиков, результат достижения читается по state/error/reason.

Коллизий, опор, баланса, физики, захвата, root/spine assistance и перестановки ног
нет. **Достижение позиции не подтверждает свободный путь руки через сцену или
тело персонажа.** Проверена текущая модель / MSVC Release / данный GPU;
межплатформенная побитовая воспроизводимость и Debug не заявляются.
