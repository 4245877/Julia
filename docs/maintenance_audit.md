## Решения о сохранности

**Безопасно удалить:** результаты текущих CTest, две старые CMake-сборки
`stage7d-baseline-cpu` и `stage7e-review`, индексы/PCH Visual Studio при закрытой
IDE, Python bytecode. Удаление ограничено конкретными проверенными путями.

**Сохранить:** все исходники и исходники тестов, FBX/BLEND/текстуры/шейдеры,
авторские backups, JSON provenance, тестовые эталоны, MuJoCo SDK, установленные
vcpkg-библиотеки, актуальный Release, `display.ini`, Git/LFS, параметры опытов,
исторические снимки исходников и сертификаты.

**Дополнительная проверка:** уникальные старые трассы, native-кадры и снимки
экспериментов. Их исследовательская ценность не опровергнута, поэтому информация
сохранена без потерь. Большие CSV/PPM/PAM/BIN перенесены в проверенные сжатые
архивы этапов; исходники, параметры, сертификаты, PNG и Markdown остаются рядом
с прежними путями. Это сохранение инженерных данных с реальным уменьшением
размера, а не перенос несжатых временных директорий.

## Формат исторических данных

`build/research-archive/<stage>-raw.zip` содержит данные и `_manifest.json`:
исходный путь относительно `build/diagnostics`, размер, mtime и SHA-256.
После уплотнения точные дубликаты одного этапа хранятся один раз; поле
`stored_path` связывает остальные исходные пути с сохранённым содержимым.
Каждый архив самодостаточен, без ссылок на архивы других этапов.

```powershell
python tools/archive-diagnostics.py verify --stage stage7k
python tools/archive-diagnostics.py restore --stage stage7k
```

Восстановление проверяет архив, отказывается перезаписывать отличающиеся файлы
и создаёт все оригинальные пути, включая дубликаты. Простая ручная распаковка
ZIP не восстанавливает aliases. Для старых readers восстановите требуемые этапы;
прежние evidence-манифесты проверяются на восстановленном наборе. Runtime-хеши
также требуют прежних исходников, CMake-конфигурации и бинарников.

`pack --prune` разрешён только для завершённых ручных опытов: оригинал удаляется
после полной проверки SHA-256 архива и проверки неизменности исходного файла.
Архив принудительно сбрасывается на диск до удаления оригиналов.
Новые данные в уже существующий архив автоматически не добавляются.

## Устранённые причины накопления

CTest писал результаты разных конфигураций в общие `build/diagnostics/stage*`.
Теперь все зарегистрированные outputs находятся под
`build/<preset>/verification/artifacts`. Старые исследования не перезаписываются,
а штатная очистка охватывает результаты новых тестов.

Два скрытых выхода обходили переданный каталог: `desktop --verify` писал
`stage4/desktop/runtime.txt`, а `arm_reach` — `stage5/cpu/solver.csv` и `motion.csv`.
Они теперь используют каталог конкретного запуска. Вычисления тела не изменены.
`stage7d_ctest.py` перенаправляет пути без учёта регистра Windows и требует новый
output-каталог, устраняя обнаруженную историческую ошибку `c:/Julia` / `C:/Julia`.

`clean.ps1` больше не удаляет весь `build/diagnostics`: там находятся также
уникальные исследования и Python-зависимости readers. Проверки границ и отказ
при symlink/junction сохранены. `.gitignore` уже покрывал build, runtime, бинарники,
логи и bytecode; добавлять общие маски не потребовалось.

Повторные серии исследований создают новые каталоги без политики хранения.
Для ценных завершённых опытов добавлен проверяемый архиватор, для обычных тестов
используется штатная очистка. Полные снимки каждого результата больше не должны
рассматриваться как обязательная часть рабочей среды.
