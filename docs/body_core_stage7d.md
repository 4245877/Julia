## Область результата

Добавлен явно включаемый `DriveMode::Servo` / `CommandKind::SmoothTarget`.
Конечная команда, опорное движение и физическое состояние разделены.
`JointDrive.cpp` — единственный источник расчёта legacy PD, servo, direct
torque, общего ограничения момента и интегрирования мощности.

```text
конечная цель → ограниченная опорная траектория → PD + feedforward
→ общий предел момента → MuJoCo → измеренные q/v → согласованный снимок
```

Выполняется прежний внешний тик 120 Гц, руки — 8×1/960 с, тело — 16×1/1920 с.
Усилие пересчитывается на каждом подшаге, мир шагает один раз на подшаг.
`PhysicsWorld` остаётся единственным писателем live q/v; исправления после
интеграции и визуального clamp нет. Кинематический `BodyInstance`, клипы, IK,
anchors и hand layers в физических приложениях не запускаются.

## Опорное движение и команды

`JointReference` строит независимую трапецию скорости для каждого hinge.
Исходные ограничения новых стендов: **0,6 рад/с**, **2 рад/с²**. Координаты
могут завершать движение в разное время; синхронизация конечностей не заявляется.
В отличие от quintic-маршрутов `ArmReach`, генератор не зависит от IK, float
кинематических поз, сертифицированных маршрутов или шестикоординатной руки.
Он подходит также для всех 41 hinges тела. Ограничения jerk нет.

При новой цели из текущих `(q_ref,v_ref)` сначала выполняется торможение
с `a=-sign(v_ref)*a_max` до остановки в
`q_stop=q_ref+v_ref*abs(v_ref)/(2*a_max)`, затем rest-to-rest движение.
Для расстояния D время разгона `min(v_max/a_max,sqrt(D/a_max))`, далее
возможны полка и симметричное торможение. Фазы интегрируются аналитически;
подшаг, пересекающий границу, разбивается внутри генератора, без дополнительного
шага мира. В конце явно устанавливаются конечная цель и нулевая скорость.
Повтор той же цели не перезапускает план.

Это консервативный генератор: перенацеливание может сначала продолжить старое
направление до остановки. Частые меняющиеся цели могут постоянно вызывать
торможение. Он не является фильтром для точного воспроизведения высокочастотного
потока целей. Новый `retarget` задаёт цели на тиках 1, 61 и 181; servo-вариант
`internal` полного тела обновляет конечные цели раз в 120 тиков. Legacy `spatial`
и `internal` сохраняют прежние синусоидальные команды при legacy-приводе.

| Вход | Принятое поведение |
| --- | --- |
| `reset(q,root)` | Disabled, q_ref=q, v_ref=0; очищены планы, ctrl, effort, силы, work, saturation, настройки servo и история; epoch увеличен |
| Первый `SmoothTarget` / вход из другого режима | q_ref=измеренное q, v_ref=0, затем план к принятой цели; live q/v не меняются |
| Следующий `SmoothTarget` | перепланирование из текущих опорных q/v, без скачка |
| `Target` | прежний Position PD и мгновенная командная опора, без feedforward |
| `Torque` | план отменён; прямой момент проходит общий предел; PD/FF=0 |
| `Disable` | план отменён, опорное положение заморожено, v_ref=0; активный момент=0 на следующем подшаге; накопленная работа сохраняется |
| Повторное включение | новый план из текущего измеренного q с нулевым v_ref |
| `configureServo` | атомарная проверка; скорость [1e−4,10], ускорение [1e−4,100], конечные; в работающем Servo настройки менять нельзя, сначала Disable |
| Неверная команда/параметры | `false` и причина; принятое состояние, план и настройки сохраняются |
| gravity на free root | явный `false` с причиной; scratch gravity query бросает `invalid_argument` |

Скорость опоры при включении специально равна нулю, даже если физическое тело
движется. Это позволяет демпфировать уже имеющееся движение; непрерывность опоры
обещается при перенацеливании внутри Servo, а не через явную смену режима.
Если измеренное q уже вышло за soft limit, начальная опора следует этому q,
затем возвращается к допустимой цели. Саму физическую координату не зажимают.
Цели проверяются по действующим инженерным пределам профиля.
Нижние границы параметров исключают underflow и длительности, которые нельзя
продвигать с физическим шагом. Расчёт фаз также проверяет конечность; новый
план всех координат готовится на копии и принимается целиком. Ошибка расчёта
возвращает отказ, сохраняя предыдущий план даже при перенацеливании.

Disable оставляет пассивное MuJoCo joint damping: у стенда руки **0,02 Н·м·с/рад**;
у тела torso/neck/head 0,5, clavicle/arm 0,15, legs 0,1. Гравитация, контакты
и ограничения продолжают действовать. Сценарии `retarget` и servo `internal`
после Disable не восстанавливают привод самостоятельно. Старый scripted legacy
`internal` по прежнему обновляет Position-команду каждый тик.

`referenceReached` означает только окончание опорного плана. Это **не**
подтверждение достижения физической цели: перегруженная рука может иметь
`referenceReached=true`, насыщение и ошибку около радиана.

## Регулятор и гравитация

```text
tau_requested = kp*(q_ref-q) + kd*(v_ref-v) + tau_gravity(q)
tau_limited = clamp(tau_requested, -maxTorque, +maxTorque)
```

Legacy сохраняет `kp*(target-q)-kd*v`. Все kp/kd, maxTorque, passive damping,
contact/limit parameters сохранены из 7А–7В. У full-arm это соответственно
`(80,8,12), (60,6,12), (12,.4,3), (40,4,8), (8,.25,2), (6,.2,1.5)`.
Только явно названный Weak использует прежние 0,35 Н·м и 2 кг payload.
Интегратора, компенсации ускорения, Coriolis или адаптации массы нет.

Проверены именно [API 3.3.7: mj_rne](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html#mj-rne),
[уравнение движения](https://mujoco.readthedocs.io/en/3.3.7/computation/index.html#general-framework)
и [реализация RNE тега 3.3.7](https://github.com/google-deepmind/mujoco/blob/3.3.7/src/engine/engine_core_smooth.c).
В уравнении `M*qacc + c(q,v) = tau + J^T*f` bias c включает гравитацию
и скоростные эффекты. Простое чтение live `qfrc_bias` не даёт чистой гравитации.

На каждом servo-подшаге с компенсацией отдельный scratch mjData сбрасывается,
получает **текущее измеренное qpos**, но нулевую qvel. Последовательность:
`mj_kinematics → mj_comPos → mj_comVel → mj_rne(flg_acc=0)`.
Без скоростей и инерционного слагаемого результат — усилие удержания против
гравитации. Passive damping, joint limits, контакты и внешние wrench в этот
RNE-результат не входят. Его знак **положительно прибавляется** к PD.
Hinge torque измеряется в Н·м; направление соответствует положительной
координате hinge. Адрес выбирается через `layout.qvel[k]`, полученный по имени
после компиляции, а не по предположению о порядке DFS. Motors имеют gear=1.

Весь PD+FF ограничивается одним maxTorque, затем независимо действуют прежние
MuJoCo ctrlrange/forcerange. Компенсация не использует `qfrc_applied`, внешние
силы, дополнительный привод или изменение состояния. Scratch queries не меняют
live q/v, tick, work или accepted commands; доступ последовательный, не thread-safe.

Для полного тела компенсация **не поддерживается**. Общий Servo работает на
всех 41 hinges, но free root остаётся недоприводным: nq=48, nv=47, nu=41.
Нет root actuator, damping, скрытого world constraint или стабилизации.
Суставное движение не является балансом или обещанием стояния.

## Нагрузки и независимые проверки

`--payload` добавляет welded-сферу 40 мм в существующем Grip, с массой,
COM и `I_COM=0.4*m*r²`. `--mass-scale` пересчитывает массу сегментов и их
COM-инерции в прежней цилиндрической модели. Масса не выводится из визуального
прикрепления. Смена нагрузки создаёт новую compiled модель. Геометрия и размеры
сегментов не меняются, поэтому их локальные COM остаются прежними, а общий COM
и масса дерева изменяются физически.

Отдельный fixture: стержень 1 м, 2 кг, COM на (+0,5;0;0), hinge +Z,
gravity −Y. Аналитическое усилие удержания `+9.81*cos(q)` проверено при
q=−0,8 / 0 / 0,6 / 1,1 рад с ошибкой <2e−15 Н·м. При max=0,35 Н·м
FF около 9,81 Н·м всё равно ограничен до 0,35, стержень начинает падать.
Для обеих нагруженных рук RNE дополнительно сравнивается с независимой
центральной разностью потенциальной энергии по всем шести координатам.

## Временной смысл телеметрии и работа

Старые `state.csv`, `joints.csv`, `contacts.csv` сохраняют формат и смысл.
Новый `drive-v1.csv` имеет `schema=1`, одну строку на hinge и tick.
В нём разделены конечная цель, endpoint q_ref/v_ref, измеренные q/v и ошибки,
последняя управляющая выборка, P/D/FF, requested/limited/actual,
насыщение последнего подшага и любого подшага тика, суммарное и непрерывное
время насыщения, мощность и работа. Глобальные энергетические поля повторены
в строках hinges с префиксом `total_`; суммировать их по строкам нельзя.

`time_s` — конец тика. `sample_time_s=time_s-h` — начало последнего подшага:
именно sample q/v/q_ref/v_ref породили записанные P/D/FF/requested/limited.
`mode` — принятый режим, `sample_mode` — режим последнего вычисления привода;
между командой и следующим шагом они могут различаться. При tick=0
управляющей выборки ещё нет: sample/torque/work поля начальные нулевые.
После интеграции генератор продвигается на h и публикует endpoint опору вместе
с endpoint физикой. `actual_Nm` — backend `qfrc_actuator`, а не ctrl.
Для данных gear=1 motors с постоянным усилием в течение подшага actual torque
одинаков при управляющей и endpoint выборках. Это свойство текущей модели,
а не обобщённое обещание для activation dynamics или нелинейных transmissions.

Endpoint power `P=tau_actual*v_endpoint`, согласованная по времени с q/v.
Для работы на каждом подшаге сохраняются фактический момент, v_before/v_after:
интегрируется линейная интерполяция двух мощностей (трапеции). Если мощность
меняет знак внутри подшага, интервал делится в её линейном нуле.
`delivered_J=integral(max(P,0))`, `absorbed_J=integral(max(-P,0))`,
`net_J=delivered_J-absorbed_J`. Обе накопленные энергии неотрицательны.
Это механическая отдача/поглощение, не электрическое потребление и не тепло.

Отдельно публикуются `-sum(damping*v²)`, его trapezoid integral,
`sum(F_world·v_COM_world + T_world·omega_world)` внешних wrench и его integral,
а также изменение `kinetic+potential` от reset. Passive damping work отрицательна.
Сила wrench удерживается один тик; её endpoint power относится к только что
завершённому подшагу. Работа контактов, friction и мягких ограничений отдельно
не интегрируется, поэтому энергетический остаток контактных случаев не считается
ошибкой одного активного привода.

Квадратура мощности имеет O(h²) глобальную ошибку для гладкой точной траектории;
ошибка самого `implicitfast` состояния в общем случае первого порядка.
В independent zero-g fixture tau=0,4 Н·м за 1 с: work=0,12 Дж,
совпадение с аналитической KE лучше 1e−14 Дж. Расхождение с `tau*delta_q`
при 8/16/32 подшагах — 0,000125 / 0,0000625 / 0,00003125 Дж:
MuJoCo обновляет положение через новую скорость, поэтому эти две дискретные
оценки не обязаны совпасть точно. При торможении поглощено 0,09 Дж.
Тест линейного перехода мощности +2→−2 Вт за 1 с даёт по 0,5 Дж обеих частей.
Отдельные проверки external-only torque и passive-only decay подтверждают
разделение источников энергии.

## Desktop, регрессии и стоимость

Desktop читает опубликованный снимок: actual skin и proxy, magenta конечная
цель руки, orange опорная цепь, ошибки, насыщение, P/D/FF/limited/actual,
power, delivered/absorbed work, passive/external work и механическую энергию.
Для тела orange reference использует текущую измеренную root-рамку; это
визуализация внутренних координат, не желаемое положение root.
Повторное рисование проверяет неизменность q/root/reference/work и pixels.

Итоговые численные логи, статистика и статусы проверок перечислены в
`build/diagnostics/stage7d/README.md`. `tools/verify_stage7d.py` запускает
реальные EXE: обе стороны × hold/retarget/retarget-no-comp/weak/impulse,
плюс body internal/drop/tilt, каждый при заданных 30/60/144 Гц.
Сравниваются все детерминированные поля старых CSV и drive-v1, timings исключены.
Это локальная воспроизводимость SDK/compiler/configuration; межплатформенная
побитовая идентичность не заявляется. Заданные кадровые интервалы не измеряют FPS.
GPU rendering, internal callbacks и ввод через ОС оцениваются отдельно.

Итоговые полные наборы: **59/59 основных, 26/26 CPU и 22/22 OFF**.
После финальной проверки численных границ входа повторены затронутые
физические и desktop-servo наборы: **8/8**. Матрицы реальных процессов:
**39/39 новых +15/15 legacy 7В +18/18 legacy 7Б**. С исходным состоянием
совпали все детерминированные поля **44 старых CSV-файлов**, без смены эталонов.

не заменяет OS-input проверку. Подробности — `native-input.txt`.

телеметрию; import, pose publication, CSV IO и GPU исключены. Сохранены все

и gravity scratch; `telemetryUs` — reference advance и joint work;
external work/endpoint energy входят в `readUs`.
P95 в C++ и сводке — отсортированный элемент с нулевым индексом floor(0,95*N).
Для сравнения с исходным кодом один `stage7d_legacy_benchmark.cpp` линкуется
также с архивным backend; одинаковые arm payload 0,5 кг и body zero-g workload.
Разность timings — наблюдение на Windows, без hard real-time гарантии.

Средний прирост явно измеряемых control/telemetry components относительно
архивного backend — около **0,82 мкс/тик руки и 9,16 мкс/тик тела**.
Gravity scratch добавляет примерно **13,57 мкс/тик руки** к servo-компонентам.

тело добавляет reference FK только в Servo. Эти затраты показаны отдельно от
физического тика. Raw samples и вычисление статистики сохранены.

## Границы и вопросы для 7Д

Этап проверяет привод и его наблюдаемость, не человеческую биомеханику.
Массы, инерции, диапазоны и proxy — инженерные. Нет ограничителя фактической
скорости/мощности, thermal/battery модели, электропотребления, мышц, обучения,
анатомических изменений, бесшовного перехода к BodyInstance или захвата.

Для **7Д — контактного управления** остаются конкретные задачи:

- определить цели контактной силы/импеданса и переходы free-motion/contact;
- отделить желаемые опорные контакты от ударов и самоколлизий, проверить
  измерение нормальных/касательных сил, трение и срыв;
- учитывать работу contact/friction/soft-limit в энергетических проверках;
- управлять доступным усилием и допустимым проникновением при насыщении,
  не зажимая физическую позу;
- для свободного тела отдельно спроектировать управление COM, распределение
  опорных реакций, баланс и критерии падения;
- проверить устойчивость на изменённых нагрузках, длительных контактах,
  временных задержках и уточнённых proxy, с прежними регрессионными порогами.
