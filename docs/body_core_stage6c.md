## Получение решений

`DirectOnly` сохраняет синхронный алгоритм и прежнюю политику команд.
Для `AllowDetour` добавлен `ArmPositionSearchJob`, сохраняющий q, ошибку, текущий seed
и номер итерации между тиками. Одна DLS-итерация используется обоими решателями;
Jacobian, damping, projected line search и координатные пределы не ослаблены.
Wrist решает четыре координаты, palm/grip — шесть; неактивное запястье сохраняется.

`DetourSettings.maxConfigurations`: **1 по умолчанию, допустимо 1–4**. Четыре —
небольшая верхняя граница, позволяющая резервировать четверть геометрического
бюджета каждой альтернативе, сохраняя ограниченный набор и один активный path job.
Одна конфигурация использует только прежние девять seeds при неуспехе IK.
Она воспроизводит углы, прямой путь и последовательность waypoint 6Б. Опорный
6Б-сценарий: кандидат **3**, **26676 запросов / 702 позы**, сегменты **114+114**.
Планирование теперь **34**, ранее 32 тика: IK тоже распределён между тиками.

Порядок общий для обеих рук, без RNG и данных о препятствиях:

1. Прежний поиск первого решения: текущая поза, середины диапазонов, затем
   `lower + (((seed*(2*k+3))%11+1)/12)*(upper-lower)`, seeds 2–8.
2. Если запрошены альтернативы, ограниченный пул seeds 0–20: те же первые девять
   приближений, затем 12 смещений текущей позы на ±0,30 ширины диапазона.
   Активная координата `((seed-9)/2)%dimensions`; результат ограничивается профилем.
   Повторные приближения также оплачиваются: никаких бесплатных рестартов.
3. На seed не более 160 итераций; всего не более 30 попыток. Неуспех seed не
   завершает многоконфигурационный поиск. Он завершается при лимите уникальных
   решений, конце конечного пула либо исчерпании бюджета — это отдельные исходы.

В список попадают только решения, прошедшие строгие пределы и **полную фактическую
FK после квантования q в float**: ошибка к исходной позиции выбранного эффектора
≤ исходного допуска. Внутренние прежние пороги solver 0,2/0,5 допуска сохранены.
Цель, эффектор и допуск не подменяются. Решение считается новым, если для каждого
сохранённого решения `max(abs(dq_active)) >= 0.08 rad` (около 4,6°).
Дубликат расходует seed/итерации/FK, но не место в наборе. Проверен также конечный
пул с одним решением и **21 дубликатом** из разных допустимых приближений.

## Порядок путей и общий бюджет

Сначала генерируется ограниченный набор. Затем проверяются прямые пути по порядку
конфигураций; принимается первый `Clear`. Если прямого маршрута нет, waypoint
перебираются по кругу: кандидат 1 для каждой конфигурации, затем кандидат 2 и т.д.
Оба реальных rest-to-rest сегмента должны завершить проверку с `Clear`.
Всего **32 waypoint-кандидата на попытку**, а не 32 на каждую конфигурацию.
Критерий — первый полностью проверенный маршрут; оптимальность не заявляется.

| Бюджет | По умолчанию | Верхний предел настройки |
| --- | ---: | ---: |
| Уникальные конечные конфигурации | 1 | 4 |
| IK-итерации за тик / всего | 16 / 8192 | 128 / 16384 |
| Начатые seeds за тик / всего | 1 / 30 | 4 / 30 |
| Waypoint-кандидаты за тик / всего | 1 / 32 | 1 / 32 |
| Геометрические позы за тик / всего | 24 / 32768 | 256 / 131072 |
| Парные запросы за тик / всего | 2048 / 1000000 | 16384 / 4000000 |

Один вызов IK завершает максимум один seed, ограничивая и число контрольных полных
FK. Итерации ограничивают реальные вычисления DLS, включая конечный Jacobian и
ограниченный line search. `fkChecks` отдельно считает полные FK кандидатов;
`poses` считает позы геометрического валидатора. Постоянная подготовка цепи и
рамок сегмента ограничена числом seeds/конфигураций/кандидатов и входит в время тика.
Целая многостартовая процедура не считается одной операцией.

После генерации N решений геометрический резерв делится поровну: `floor(total/N)`,
остаток — первым конфигурациям. Прямой путь и все обходы одной конфигурации
расходуют **один и тот же её резерв**. Общие счётчики никогда не сбрасываются.
Первая конфигурация не может израсходовать резерв остальных. Неиспользованные доли
не перераспределяются; это сознательное ограничение поиска. Поэтому
`BudgetExhausted` может означать исчерпание закреплённых долей при неполном общем
расходе; публикуются причина и стадия. Сверхмалого бюджета может не хватить даже
на один запрос каждой конфигурации.

`Paused` сохраняет незавершённую работу; `stage` показывает IK/direct/первый/второй
сегмент. Отличаются `IkFailed`, конец пула IK, `Exhausted`, `BudgetExhausted`,
`CheckIncomplete`, `InvalidInitial` и причины отдельных конфигураций.
`Incomplete` не разрешает движение: конфигурация выводится из поиска, остальные
могут продолжить работу. Исходное пересечение останавливает всю попытку, поскольку
её начало общее. Время служит только телеметрией.

## Исполнение, владение и наблюдения

Геометрический код 6А/6Б не изменён: прежние формы/фильтры, margin **2 мм**,
numericSlack **30 мкм**, адаптивная проверка межтиковой интерполяции, ограничения
сегмента **8192 позы / 250000 запросов / глубина 18**. Непроверенный путь не исполняется.
Сохраняются конкретные float q, коэффициенты, длительности и сертификаты сегментов;
при исполнении повторного IK нет. В waypoint остаётся неподвижный тик.
Успех измеряется после settling по фактической FK относительно первоначальной цели.

Поиск начинается в покое после текущего разрешённого сегмента. Сцена, корень,
остальные части тела и исходные условия фиксированы. Сохранены резерв старого
разрешённого действия, восстановление после отказа Start/Retarget, команда/ID/эпоха,
Cancel из покоя и завершение только текущего сегмента при отмене движения.
Принятый `route` отделён от последующей попытки `planning`; новая генерация не
меняет его конечные q и сертификаты. При возобновлении прежнего второго сегмента
его фактический стартовый тик обновляется по прежнему контракту 6Б.
Reset, эпоха, root teleport и mode change уничтожают jobs/остаток маршрута.

Наблюдения содержат стадию, завершение IK-пула, seeds, итерации, дубликаты,
уникальные q/FK-ошибки, выбранную конфигурацию, общие и потактовые расходы,
исходы/геометрические причины по конфигурациям, waypoint, сегменты и целевую ошибку.
Потактовые счётчики равны нулю при исполнении/удержании без работы планировщика;
исторический учёт принятого маршрута остаётся неизменным.
Desktop показывает пурпурную конечную позу руки и зелёный/голубой проверенный маршрут.

## Воспроизведение и границы

Прямые CMake-команды — в VS x64 Developer PowerShell. Зависимости установлены.
В sandbox Ninja не продолжил сборку; штатные сборки выполнены с разрешённым
расширенным доступом. Один поздний повтор временно не был запущен из-за лимита
автоматической проверки разрешения; после возобновления он выполнен успешно.

```powershell
.\tools\build.ps1 -UseInstalledDependencies -KeepDiagnostics
cmake --preset cpu-release -DJULIA_WARNINGS_AS_ERRORS=ON
cmake --build --preset build-cpu-release --parallel 4
ctest --preset test-cpu-release
.\build\cpu-release\apps\julia_body_sim\julia_body_sim.exe --collision-demo multik --allow-detour --ik-configurations 1 --ticks 1200 --output build/diagnostics/stage6c/headless-one.csv
.\build\cpu-release\apps\julia_body_sim\julia_body_sim.exe --collision-demo multik --allow-detour --ik-configurations 4 --ticks 1200 --output build/diagnostics/stage6c/headless-four.csv
.\build\cpu-release\apps\julia_body_sim\julia_body_sim.exe --collision-demo blocked --allow-detour --ik-configurations 4 --ticks 1200 --output build/diagnostics/stage6c/headless-waypoint.csv
.\julia_desktop\julia_desktop.exe --verify-multik build/diagnostics/stage6c/gpu
.\julia_desktop\julia_desktop.exe --window --no-save
```

В свежем окне: F2 → Shift+F11 (demo) → F12 (AllowDetour) → Shift+F12 (4 решения)
→ F7. Shift+F12 переключает 1/4 для следующего запроса. CLI также задаёт budgets
IK/поз/запросов, retarget/cancel, сторону, эффектор и Body/World.

Поиск конечный и неполный: неуспех не доказывает отсутствие любого возможного пути.
Гарантия относится к прежним девяти капсулам и статичной сцене, а не ко всему мешу.
Ориентация кисти, динамические препятствия, две движущиеся руки, опоры, захват,
баланс и физическая динамика не добавлены. Детерминизм проверен на данном asset/MSVC
Release; межплатформенная побитовая идентичность не заявляется.
Следующий ограниченный подэтап **6Г**: явное предпочтение положения локтя и
детерминированное ранжирование полностью проверенных маршрутов внутри того же
бюджета, чтобы управлять выбором позы без расширения геометрических обещаний.
