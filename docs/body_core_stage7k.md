# Согласованный малый перенос COM и нагрузки двух стоп: stage7k

12 ноября 2026, C++20, Windows x64, MSVC Release `/WX`, MuJoCo **3.3.7**.
Материалы, карта доказательств и команды — [stage7k/README.md](../build/diagnostics/stage7k/README.md).

⟦STATUS⟧

Одна атомарная команда задаёт пару {горизонтальное смещение COM, доля левой стопы
alpha}. Обе reference строятся от текущих значений и производных на **одном времени
и одной сертифицированной длительности**, обе задачи решаются в одном QP, а
результат засчитывается только при одновременном выполнении всех фактических
условий по COM, alpha и опорам после остановки обеих reference.

## Исходное состояние и неизменяемые условия

Принятый stage7j закоммичен как HEAD `a8a5ab2`, дерево было чистым. До правок
совпали **345/345** runtime и **8907/8907** evidence хешей stage7j; сохранены 370
файлов (142,6 МБ) исходников, тестов, инструментов, настроек сборки, бинарников и
отчётов: [baseline](../build/diagnostics/stage7k/baseline/summary.json). Прежние
отчёты и каталоги опытов не перезаписывались; инструкций AGENTS.md/CLAUDE.md нет,
`.agents` пуст.

Сохранены 20 сегментов, 55 кг, 41 суставной привод и свободный таз,
`nq=48/nv=47/nu=41`, SI/Y-up, массы, инерции, геометрия, трение 0,6, номинальная
мягкость контактов 0,01 с, damping, caps, подготовленная поза и частоты: внешний
тик 120 Гц, 16 подшагов `mj_step` по 1/1920 с, четыре обновления контроллера
480 Гц. Нового поиска позы нет. Gains и веса прежние: posture 100/20 (вес 1),
COM 40/12 по горизонтали и 100/20 по вертикали (вес 900), ориентация 100/20
(вес 100), load-задача stage7j с весом 1. Root и стопы свободны; контроллер
выдаёт только 41 суставной момент. Нет записи q/v, якорей, скрытой коррекции
основания и управляющих внешних сил; reset выполняется явно в начале опыта.
Номинальный `model.xml` побайтно совпадает с принятыми stage7j и stage7i.

`Equality7g` остаётся default, явный `Bounded7h` по-прежнему использует
`Reference7h`, `Optimized7i` выбирается явно. Отдельные режимы `comCommands`
(stage7h) и `loadCommands` (stage7j), их API, правила конфликтов и CSV-схемы не
изменились. Все старые пути контроллера сохраняют прежнюю арифметику при
`coordinatedCommands=false`; это подтверждено точными сравнениями историй ниже.

## Новый согласованный режим и атомарная команда

`StandSettings::coordinatedCommands=true` включает новый режим. Он требует
`Bounded7h` + `Optimized7i` (CLI: `--bounded-solver optimized`), исключает
`comCommands` и `loadCommands`; в нём отдельные COM/load API отвергаются, а вне его
отвергаются согласованные. Всеми hinges по-прежнему владеет один `DriveMode::Stand`.

```cpp
struct CoordinatedTarget { std::optional<glm::dvec2> comOffset; std::optional<double> alpha; };
bool standCoordinatedTarget(const CoordinatedTarget&, std::string* reason=nullptr);
bool cancelStandCoordinated(std::string* reason=nullptr);
bool returnStandCoordinated(std::string* reason=nullptr);
```

Смещение COM задаётся в метрах по X/Z горизонтальной рамки постановки,
зафиксированной `startStand`, относительно исходной цели COM; alpha — абсолютная
доля `Fn_left/(Fn_left+Fn_right)`. Отсутствующий компонент сохраняет принятую
конечную цель (мировую цель COM либо абсолютную alpha) без пересчёта через рамку.
Хотя бы один компонент обязателен. Одна команда имеет один serial, одну фазу
Idle/Moving/Settling/Reached/Cancelled/Failed и один результат.

Обе кривые строятся во временных массивах; состояние меняется только если обе
прошли проверки. Иначе — отказ с причиной, а serial, обе конечные цели, обе
кривые, обе reference и физическое состояние остаются прежними. NaN/Inf, радиус
COM >5 мм, |alpha−alpha0|>0,05, alpha вне [0,1; 0,9], пустая команда, отсутствие
калибровки, не Holding или недостоверные опоры отвергаются. Пользовательская цель
никогда не проецируется. Alpha0 калибруется прежним способом stage7j: среднее по
времени всех достоверных завершённых подшагов на [2,4) с при Holding, Fn≥30 Н,
COM≤0,5 мм и скорости≤1 мм/с; до калибровки команды отвергаются. Получено
**alpha0=0,4069532857042767** — тот же baseline, что у stage7j (среднее
endpoint тиков 240–479 равно 0,4069532557777803 и показано отдельно).

`coordinatedComTask`/`coordinatedLoadTask` — исследовательские ablation тех же
команд для причинного сравнения: выключенная reference публикуется, но не входит
в QP (при выключенной COM-задаче цель COM контроллера остаётся исходной).

## Согласованное планирование

Каждый компонент — quintic Bezier `b0=p, b1=p+vT/5, b2=p+2vT/5+aT²/20,
b3=b4=b5=goal`, т. е. непрерывные значение, скорость и ускорение в момент команды
и покой в цели. Длительность **общая**: кандидаты `2·1,2^k`, k<40; кандидат
принимается, только если при **этой же** длительности обе полные кривые проходят
сертификат выпуклых оболочек после четырёх subdivisions для смещения, скорости и
ускорения: COM радиус ≤5 мм, ≤1 мм/с, ≤2 мм/с²; |alpha−alpha0|≤0,05, ≤0,02/с,
≤0,04/с². Две независимо найденные длительности не используются. Бюджет
детерминированный (≤40 попыток, фиксированные массивы).

Retarget обоих компонентов, retarget одного компонента с сохранением второй
конечной цели, отмена и возврат используют тот же планировщик. Отмена формирует
собственные stop goals `reference+velocity·1с`: COM проецируется в круг 5 мм
только если выходит за него, alpha ограничивается alpha0±0,05; обе цели
публикуются в статусе и CSV. Первый кандидат отмены — `min(2 с, остаток
принятой кривой)`. Отказ планирования сохраняет принятую команду. Возврат —
отдельная команда к паре (0; 0; alpha0).

Длительности основного цикла: A 5,972 с, B 12,383 с, C 10,320 с, возврат
5,972 с (остановка reference на 9,975/32,392/52,325/63,975 с). В B и возврате
длительность задаёт COM, в C — alpha: общая длительность больше каждой
частной там, где компоненты различаются. Флаг остановки по накопленному времени
может отставать на один подшаг от фактического достижения цели кривой; reader
считает остановку только при одновременных флаге и |ref−goal|,|v|,|a|≤1e−12.

## Обе задачи в одном QP

Используется прежняя совместная постановка: **71 переменная, 18 равенств,
124 неравенства** — динамика свободного основания, контактные ускорения, ±caps
41 привода, неотрицательные нормали углов, внутренняя пирамида трения
`|fx|+|fz|≤0,6fy` и Fn≥30 Н каждой стопы. COM-задача отслеживает общую
COM-reference с прежним feedforward `12·v_ref+a_ref`; load-задача добавляет
`row·rowᵀ`, `row=((1−alpha_ref)Fn_L−alpha_ref Fn_R)/100 Н`, вес 1. Обе мягкие
задачи одновременно выбирают ускорения и силы, моменты восстанавливаются из
динамики. Прогнозные силы не прикладываются к телу. Силовой обратной связи и
интегратора нет (`integral=feedback=0`): первичный вариант прошёл фактические
критерии. Диагностический фильтр stage7j в управлении не участвует.

## Границы результата

Левая стопа в состояниях с alpha0+0,05 при исходном и Z-смещённом COM переносит
CoP к своей внутренней кромке: минимальный запас CoP до края подошвы 0,065 мм
(C, удержание) и 0,061 мм (возврат из C); у A он 1,52 мм. У принятого stage7j при
alpha0+0,05 запас был 0,070 мм — это свойство перераспределения при неподвижном
COM, а не новый эффект. Запас CoP не входит в критерии и не ослаблялся; при этом
обе опоры оставались loaded/active, без скольжения. Для больших alpha, больших
переносов или более сильных воздействий нужны явные ограничения запаса CoP/кромки.

Область этапа — согласование существующих малых целей при двух опорах около
принятой позы: COM ≤5 мм, alpha0±0,05, толчки 3 Н×0,1 с. Отрыв стопы, одноопорная
стойка, шаг, ходьба, расширение диапазонов, более сильные воздействия, хват и
обучение не сертифицируются. Hard real-time не заявляется.
