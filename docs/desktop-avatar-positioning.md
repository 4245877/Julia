# Desktop Avatar: привязка к панели задач

Проверено 8 ноября 2026 года. Готовая Release-сборка:
`julia_desktop/julia_desktop.exe`.

## Установленная причина

В прежнем `avatarLayout` один отступ 12 DIP применялся справа **и снизу**:

```cpp
windowY = workTop + workHeight - margin - avatarHeight;
```

Поэтому даже правильно обрезанная по пояс модель висела над панелью на
`round(12 * dpiScale)` физических пикселей. В сохранённом исходном framebuffer
383 × 380 нижних прозрачных строк было **0**; композиция камеры не была причиной.
Исправлена формула окна. Его нижний край остаётся внутри рабочей области,
переноса окна под панель задач нет. Геометрия модели и анимационные данные не менялись.

## Расчёт

`L,T,W,H` — рабочая область выбранного монитора в физических пикселях,
`d` — effective DPI scale, `a` — постоянное соотношение сторон `AvatarCamera`,
`D` — сохранённая высота в DIP (по умолчанию 380), `M` — правый отступ в DIP
(по умолчанию 12). Размеры рабочей области положительны.

```text
m = min(round(M*d), floor(min(W,H)/8))
g = clamp(sqrt(min(W,H)/(1440*d)), 1, 1.25)
h = max(1, round(min(D*d*g, H/2, 0.60*(W-m)/a)))
w = clamp(round(h*a), 1, W-m)
x = L + W - m - w
y = T + H - h
```

Санитизация входов: `D` ограничен 180–720 DIP, `M` — 0–240 DIP, `d` — 0,5–8,
`a` — 0,25–4; NaN/Infinity заменяются безопасными значениями. Неположительные
размеры рабочей области приводятся к минимуму 1 px. На экранах нормального размера
округление ширины даёт не более половины пикселя отклонения от пропорции камеры.
Для вырожденной области 1 × 1 приоритет имеет попадание внутрь области.

До 1440 DIP по короткой стороне сохраняется исходная логическая высота.
Выше неё рост плавный, максимум 25%. Ширина ультраширокого монитора сама по себе
не увеличивает портрет. Маленький экран ограничивает размер половиной высоты
и 60% доступной ширины. Это учитывает разрешение, эффективную плотность/DPI
и пользовательский размер без предположения о соотношении сторон монитора.

Нижний край прямоугольника является **исключающей** координатой. Если framebuffer
не имеет пустых строк снизу, его последний видимый пиксель находится на
`workBottom - 1`, непосредственно перед первым пикселем панели. Проверяемый зазор:

```text
gapPx = workBottom - (windowY + avatarHeight - emptyBottomRows)
```

В проверенной Windows-конфигурации framebuffer и borderless client имеют одинаковые
размеры в физических пикселях; это проверяется native/GPU-тестами, а не предполагается
по коэффициенту DPI.

### Камера

Существующая фронтальная ортографическая камера сохранена. Её нижняя плоскость —
распознанный нижний spine-узел в bind-позе, либо fallback 51% высоты модели.
Верхняя плоскость — верх геометрии плюс 4,5% полной высоты модели. При движении
скелета обе плоскости переносятся на смещение опорного узла. Высота проекции
постоянна; новые bounds, автоувеличение и коррекция по alpha на каждом кадре
не применяются. Измерение alpha используется только для регрессионной проверки.

## Окно, DPI, мониторы

- `glfwGetMonitorWorkarea` на Windows уже использует `GetMonitorInfo.rcWork`.
  Дублировать его отдельным определением высоты панели не требуется.
- Рабочие координаты не умножаются на DPI. Масштабируются только DIP-размер
  и отступ. `GLFW_SCALE_TO_MONITOR` отключён явно, чтобы размер не применялся дважды.
- `WindowPlatform::applyAvatarRect` устанавливает положение и размер одним
  `SetWindowPos`, сохраняя фокус и порядок окон.
- По умолчанию используется основной монитор. F10 из Full Window выбирает монитор
  этого окна через `MonitorFromWindow`/`GetMonitorInfo`; device name сохраняется
  в `avatar_monitor`. Если выбранного устройства нет, используется основной.
- Проверка каждые 0,5 с повторно получает рабочую область/DPI и сверяет фактический
  прямоугольник, исправляя также внешнее смещение окна. Идентификаторы GLFW-мониторов
  между проверками не кешируются.
- Для верхней/боковой панели сохраняется привязка к нижнему краю фактической рабочей
  области. Auto-hide следует системной рабочей области, включая зарезервированную
  полосу вызова, если Windows её возвращает.
- Старые `display.ini` читаются с прежними значениями по умолчанию. Новые поля:
  `avatar_margin_right_dip` и `avatar_monitor`. Запись остаётся атомарной.

О координатах и DPI: [GLFW Window guide](https://www.glfw.org/docs/3.4/window_guide.html),
[GLFW Monitor reference](https://www.glfw.org/docs/3.4/group__monitor.html),
[Win32 backend GLFW 3.4](https://github.com/glfw/glfw/blob/3.4/src/win32_monitor.c).

## Изменённые компоненты

| Компонент | Изменение |
| --- | --- |
| `DisplaySettings.hpp/.cpp` | Нижняя привязка без отступа, адаптивный размер, правый отступ и выбор монитора в INI |
| `WindowPlatform.hpp/.cpp` | Выбранная рабочая область, определение монитора окна, атомарное размещение |
| `DisplayController.hpp/.cpp` | Выбор дисплея через F10, актуализация положения, удаление устаревшего кеша |
| `main.cpp` | Явное отключение второго DPI-масштабирования, измерение покрытия и проверка композиции |
| `test_desktop_display.cpp` | Матрица layout, INI, native-границы, DPI/client/framebuffer, перенос между мониторами |
| `docs/desktop.md`, `docs/desktop-avatar.md` | Настройки, формулы, поведение мониторов и ограничения |

`AvatarCamera`, renderer, материалы, модель и полнооконная камера не изменены.
Новые зависимости не добавлены.

## Проверки

Release/MSVC x64 собран командой `tools/build.ps1 -UseInstalledDependencies -SkipTests`.
Итоговый `ctest --preset test-release`: **17/17 passed**, 40,38 с.

- 18 900 математических конфигураций: 1080p, 1440p, 4K, 16:10, 21:9, 32:9, 4:3,
  портретный экран, маленькие и вырожденные области; DPI 100%, 125%, 150%, 175%,
  200%, 225%, 300%; панели на четырёх сторонах/без резерва; отрицательные X/Y;
  разные размеры и пропорции аватара.
- Native-тест прошёл на обоих подключённых дисплеях:
  `DISPLAY1`: `(0,0) 2560×1392`, DPI 100%;
  `DISPLAY2`: `(-1280,113) 1280×976`, DPI 100%.
  Проверены клиентские координаты Windows, framebuffer, восстановление после
  внешнего смещения и выбор монитора при F10.
- Реальный GPU-рендер: 15 клипов × 9 временных точек, 12 размеров viewport,
  увеличение размера и возврат режима — всего 152 портретных кадра.
  Во **всех** кадрах снизу 0 пустых строк. В 135 анимационных кадрах запас сверху
  35–63 px при высоте 380 px. Высота проекции неизменна: `0.991737`.
- Для основного монитора 2560×1440 с нижней панелью высотой 48 px:
  окно `(2165,1012) 383×380`, исключающая нижняя граница `1392`, последний
  видимый ряд `1391`, верх панели `1392`, зазор **0 px**.
- Пройдены проверки F9, шести переключений F10, сохранения камеры и playback,
  прозрачности, MSAA, premultiplied sRGB, прохода мыши через пустые области,
  изменения native-региона, чтения/сохранения старых и новых настроек.

### Что проверено визуально

Собранное приложение запущено на видимом рабочем столе 2560×1440. Через computer-use
осмотрены прозрачный портрет 383×380, его нижняя граница, запас для ушей/головы,
анимация `TEST_blink_head`, меню, переключение F9 и переход F10 в полноценную сцену
и обратно. Тестовый запуск использовал `--no-save` и был закрыт по завершении.
Визуально проверена также контактная таблица реальных GPU-кадров всех 15 клипов.

Скриншот инструмента ограничен прямоугольником окна и не включает соседнюю панель
задач целиком. Поэтому совпадение с её границей дополнительно подтверждено
независимыми координатами рабочей области, native client и покрытием alpha последней
строки. Физические разрешения/DPI Windows не переключались. Другие DPI и положения
панели проверены расчётами и рендером соответствующих размеров; живое изменение
auto-hide, расположения панели и DPI на отдельном оборудовании не проверялось.

Артефакты в `build/vs-release/verification/desktop_display/`:

- `coverage.csv` — измерения всех портретных кадров;
- `avatar.png` — прозрачный GPU-кадр при стандартном размере;
- `portraits.png` — таблица 15 клипов и нескольких размеров (голубая линия — край
  кадра, а не изображение настоящей панели задач);
- `*.pam` — исходные кадры GPU. PNG экспортированы из premultiplied RGBA с
  восстановлением straight alpha для корректного просмотра.

Полный протокол CTest: `build/vs-release/Testing/Temporary/LastTest.log`.
