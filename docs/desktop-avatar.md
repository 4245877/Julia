# Desktop Avatar и Full Window

В обоих режимах живут одни `GLModel`, `AnimationPlayer`, `EyePoseLayer` и
`OpenGLRenderer`. Переключение меняет оформление/геометрию того же GLFW-окна,
камеру и назначение вывода. WGL-контекст, GPU-ресурсы и состояние playback остаются.
По умолчанию при отсутствии сохранённых настроек включён Desktop Avatar.
Команды запуска и управления описаны в [desktop.md](desktop.md).

## Окно и композитинг

GLFW 3.4 создаёт окно с `GLFW_TRANSPARENT_FRAMEBUFFER`, восьмибитным alpha,
sRGB и MSAA. Возможность прозрачного framebuffer задаётся при создании в обоих
режимах: GLFW не позволяет включать её атрибутом существующего окна.
`GLFW_DECORATED`, `GLFW_RESIZABLE` и `GLFW_FLOATING` меняются при переключении.
Приложение проверяет реальный `GLFW_TRANSPARENT_FRAMEBUFFER`. Если прозрачность
недоступна, запуск продолжается в обычном окне с диагностикой.

На Windows GLFW использует DWM. Нет скриншота рабочего стола, цветового ключа,
общей полупрозрачности окна и отдельной копии рендерера. Полнооконный вывод
остаётся прежним: default framebuffer и непрозрачный sRGB `#808080`.

В Desktop Avatar `AvatarSurface` предоставляет рендереру multisampled RGBA16F
FBO с depth. Он очищается в `(0,0,0,0)`. Те же проходы рисуют непрозрачные,
маскированные и полупрозрачные материалы, skinning, тени и контуры. После resolve
в RGBA16F текстуру получается premultiplied **linear** RGB и покрытие alpha.
Финальный проход вычисляет:

```text
straight_linear = alpha > 0 ? linear_rgb / alpha : 0
desktop_rgb = linear_to_srgb(straight_linear) * alpha
desktop_alpha = alpha
```

Запись выполняется с отключёнными sRGB-конверсией и blending. Это даёт DWM
premultiplied RGB в пространстве экрана. Простое очищение default framebuffer
прозрачным чёрным недостаточно: sRGB-конверсия premultiplied linear RGB создаёт
светлые ореолы на частичном покрытии. Resolve сохраняет MSAA краёв, а отдельный
alpha blend factor `ONE, ONE_MINUS_SRC_ALPHA` уже используется общим рендерером.

## Мышь

`WindowPlatform` — единственный адаптер native-окна Windows. Он строит `HRGN`
по ненулевому alpha разрешённого FBO: горизонтальные непересекающиеся интервалы
сверху вниз передаются `ExtCreateRegion`, затем `SetWindowRgn`. Нулевой alpha
исключается; любое ненулевое покрытие сохраняется, включая полупрозрачные края.
Регион ограничивает геометрию окна, а дробную прозрачность продолжает считать DWM.

Это даёт системное прохождение мыши к окнам других процессов. Возврат
`HTTRANSPARENT` из `WM_NCHITTEST` сам по себе ограничен окнами того же UI-потока;
постоянный `GLFW_MOUSE_PASSTHROUGH` отключил бы взаимодействие и с персонажем.
Сравнение интервалов позволяет не менять неизменный регион. Windows получает
владение HRGN при успешном вызове; при ошибке ресурс освобождается приложением.

Порядок каждого кадра: **рисование вне экрана → resolve → чтение alpha → новый
регион → вывод в окно → swap**. Так предыдущий регион никогда не обрезает новые
участки движущегося силуэта. Перед сменой режима или размера регион сбрасывается.
Системное тестирование `WindowFromPoint` проверяет целевое окно внутри силуэта
и прохождение к другому окну снаружи, без синтетического ввода пользователю.

Координаты курсора и события GLFW остаются доступны сцене. ЛКМ по персонажу
зарезервирована для будущего взаимодействия; ПКМ открывает системное меню.
Камера Desktop Avatar не реагирует на орбитальные жесты, поэтому её композиция
не теряется при кликах. F10/F9 работают, когда окно имеет фокус. Глобальных
перехватчиков клавиатуры, мыши и служебных невидимых окон нет.

## Камера и рабочая область

`AvatarCamera` в `julia_render` не зависит от GLFW, Windows и OpenGL.
Она использует преобразованные в сцену реальные bind-габариты. Для распознанных
ригов нижняя граница кадра проходит через нижний spine-узел; у неизвестных ригов
есть пропорциональный fallback на 51% высоты. Верх включает реальные уши/волосы
и запас 4,5% высоты модели. Ширина учитывает реальные габариты и боковой запас.

Ортографическая фронтальная камера сохраняет пропорции на всех глубинах,
а нижняя граница изображения совпадает с плоскостью пояса. Нижнее тело выходит
за естественные границы кадра; геометрия не удаляется и не режется scissor либо
near plane. Отдельный параметр `CameraConfig::orthographicHeight` выбирает эту
проекцию; значение 0 сохраняет прежнюю перспективную камеру Full Window.

Перемещение опорного spine-узла в анимации переносит портретную камеру вместе
с телом через уже рассчитанные `AnimationPlayer::globalTransforms()`. Камера не
следует за глазами и не меняет масштаб от моргания/волос. Полнооконная
`OrbitCamera` не получает компактный viewport: это сохраняет также широкое
панорамирование, которое иначе могло бы обрезаться её ограничителями.

`avatarLayout` рассчитывает размер из логической высоты, DPI основного монитора
и соотношения сторон портрета. Используются `glfwGetMonitorWorkarea` и
`glfwGetMonitorContentScale`, а не фиксированные экранные координаты. Рабочая
область учитывает панель задач с любой стороны, отрицательные координаты
мониторов и ограничение доступного пространства. Раз в 0,5 с проверяются её
изменения, включая смену основного монитора. Высота по умолчанию 380 DIP,
отступ 12 DIP; на небольшом экране размер уменьшается с сохранением пропорций.
Компактный цикл ограничен примерно 60 кадрами/с, даже если драйвер игнорирует VSync.

## Настройки и ограничения

Небольшой переносимый `display.ini` рядом с EXE хранит режим, topmost, размер
портрета и геометрию/максимизацию Full Window. Чтение проверяет допустимые значения;
неизвестные/повреждённые поля заменяются значениями по умолчанию. Запись идёт через
временный файл и атомарную замену. Каталог должен быть доступен для записи;
при ошибке приложение продолжает работать и сообщает её в stderr. Автотесты
изолированы от пользовательских настроек. Окно показывается после первого кадра,
без прямоугольной вспышки при загрузке FBX.
При запуске EXE отдельно созданная для него консоль скрывается в Desktop Avatar
и возвращается в Full Window; уже открытая пользовательская консоль не скрывается.

На данный момент адаптер per-pixel input region реализован для Windows;
на других системах доступен Full Window. Для Windows нужны рабочие DWM и драйвер
OpenGL 3.3. Remote Desktop, разные GPU и переключение физических DPI/мониторов
не проверены на отдельном оборудовании. Автотесты покрывают расчёты при 100%,
125%, 150%, 200%, 300%, разные рабочие области и отрицательные координаты.

Чтение небольшого RGBA framebuffer на CPU синхронное: это предсказуемый способ
согласовать видимый кадр и native hit testing без задержки маски. При дальнейшем
увеличении окон/числа персонажей следует измерить стоимость и рассмотреть
асинхронное GPU-чтение. Анимации, существенно выходящие за bind-габариты
(например, высоко поднятые руки), могут выходить за края портрета; автоматического
изменения масштаба на каждом кадре нет, чтобы не создавать скачков композиции.
Существующая сортировка blended-материалов по центрам mesh сохранена; OIT не добавлен.
